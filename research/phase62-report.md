## 3. 读法：Phase 61 的两个数字都不是 5-seed 结论

### 3.1 「分化 22 → 20（−9 %）」是 3-seed 盆地噪声

5-seed 上同一对比是 **31 → 33（+6.5 %）**，方向反转。反转来自两个此前从未观测的 seed：20261107 7 → 11、20261109 3 → 5；而 102（9 → 8）与 42（10 → 7）仍是负号。也就是说：b 臂对分化的影响是 **seed 符号不一致**，合计落在噪声带里，既不能声称「b 抑制分化」，也不能声称「b 提升分化」。

结论上这一点很重要：Phase 61 的验收把「分化不降」写成并列条件，而 −9 % 恰好落在 3-seed 的分辨率内；5-seed 证明它确实是噪声，**b 的真实代价不是分化**。

### 3.2 「灭绝 13 → 4（−69 %）」同样是 3-seed 盆地噪声

5-seed 上 **17 → 15（−12 %）**，远不到预注册的 −50 %。逐 seed 看，Phase 61 的全部收益来自 seed 42（8 → 1）：

- 42：8 → 1（−7）——个案，不是规律；
- 102：4 → 2（−2）；
- 109 / 05：不变；
- **07：1 → 8（+7）——符号直接反转**。

非判定性的 20261113 也是同向反转（1 → 6）。所以「b 让灭绝减半」在 5 个 seed 上有 **2 个反向/大幅反向**，合计 −12 %。

### 3.3 机制：floor ≥ 每个女儿的自然份额 ⇒ 区域闸对女儿整体失效

Phase 61 §4.1 的 b 规则是 `cap_occ = max(budget·w/Σw, min(budget, 8))`。而 Phase 49 的 fork 预算给所有派生 kind 的预算 ≤ `FORK_BUDGET_GRANT = 20`，均场权重下的自然份额 ≤ 5 < 8 —— **floor 对每一个女儿支都高于自然份额**，于是：

- budget ≤ 8 的女儿：`floor = budget`，占据象限的 cap 等于它的全部预算 ⇒ 区域闸完全不再约束它，只剩 Phase 49 的 kind 预算闸；
- budget 11–15 的女儿：cap 从 2.75 / 3.75 抬到 8，四象限合计 32 > budget ⇒ 同样是 kind 预算闸先命中；
- budget 20 的第一代女儿：cap 5 → 8，单象限仍会命中，但两象限起就不再是区域闸。

实测证据是区域拒绝记账：**OFF 臂 17 起灭绝里 15 起的 `region_cap_blocks > 0`（78 – 158 343）；b 臂 15 起里只有 2 起 > 0**。b 臂的灭绝支系改为被自己的 **kind 预算**顶住（除 #15 的流产建支与 05 的 scav 根外，`kind_budget_blocks / (kind_budget_blocks + births) ≥ 99.6 %`），即「象限挤压」被换成了「支系自身份额的上限」。

这解释了为什么灭绝没有减半：b 没有消除容量矛盾，它只是把矛盾从**区域份额**搬到了**kind 预算**上。一个 8-budget 的女儿支即使在四个象限都被 floor 保护，全族也只有 8 个槽位；它仍然是一个「在 8 个成员时被宣布为物种、然后按 8 个槽位做人口学随机游走」的支系。

## 6. 决策

**不通过 → 默认保持 Phase 60/61 世界（b 臂 OFF），不发生第十八次 re-baseline。**

依据：预注册 §1.4 第 4 条 —— P2（灭绝 ≤ 0.5 × OFF）失败。b 臂的唯一提升理由是「拿分化换灭绝减半」；5-seed 上分化没有代价（33 vs 31，P1 通过），灭绝也没有收益（15 vs 17，−12 %，且 07 上 +7 反向），交换的两端都不成立，因此没有理由翻默认。

同时必须写清楚**否定了什么、没有否定什么**：

- 否定的是 Phase 61 的**两个 3-seed 数字**：分化 22 → 20 是盆地噪声（5-seed 上 31 → 33），灭绝 13 → 4 也是盆地噪声（5-seed 上 17 → 15）。这两个数字都不应再被引用为 b 臂的性质。

## 10. Phase 63 遗留

1. **「象限挤压」已经证伪为 b 的可解问题**：b 把 `region_cap_blocks` 从 15/17 清到 2/15，灭绝只降 12 %。真正约束女儿支的是 Phase 49 的 **kind 预算**（8–20 槽），不是区域份额。Phase 63 若要继续「让新物种活下来」，应直接动 kind 预算的最小值（`FORK_BUDGET_MIN = 8` 与 `SPECIATION_MIN_SIDE = 8` 的对偶），而不是区域份额；但那会改 `family_budget_total` 守恒（DECO 全族 80 的固定总额），需要先回答「新增预算从哪来」。
2. **流产式建支（§4 #15）是新档失败模式**：fork 通过 `MIN_SIDE = 8` 后 4 000 tick 内耗散、两道容量闸都没命中。Phase 63 的定因框架应加一档「建支即失稳」，判据建议 `peak ≤ 12 ∧ region_cap_blocks = 0 ∧ budget_blocks = 0 ∧ 生存 < 10k`。
3. **灭绝率的 seed 依赖远大于臂效应**：5-seed OFF 的逐 seed 灭绝是 4 / 8 / 1 / 3 / 1，b 是 2 / 1 / 1 / 3 / 8。任何「灭绝率」结论都必须给逐 seed 分布（Phase 61 §9.5 已写，本期再次印证）。
4. **判据本身的问题**：本期 P2 的「减半」门槛来自 Phase 61 的 3-seed 观察（13 → 4），事后看是拟合出来的门槛。Phase 63 若要重设，应把「灭绝」拆成 DECO 家族口径（排除 05 scav 这类跨家族固定事件）并给出绝对区间，而不是相对比例。
5. **变体 d 的结论**（§5）与上述 1 的关系需要联动读：d 保留第一代 20-budget 女儿的区域分割、只放开 15/11/8 预算的孙代；它回答的是「哪一代被挤死」，不回答「预算不够」。实测 d（30 / 18）与 b（33 / 15）、OFF（31 / 17）三者同一量级且方向不一致，**「floor 高度」不是杠杆**——这是「容量份额类修正」的一个否证性结论，Phase 63 不应再在 region cap 上做参数微调。
6. **b 臂真正有效的子机制只有一条**：把第一代 20-budget 女儿的区域分割拿掉（b 相对 d）能提高分叉数（33 vs 30），代价是灭绝 +3（15 vs 18）。如果 Phase 63 要继续这条线，它应该被当成「fork 率旋钮」而不是「灭绝旋钮」来标定（例如：在保持灭绝不升的前提下求最大 fork 率）。
7. `region_cap_blocks` 的闸门顺序盲区（Phase 61 §9.4）仍未修；本期 b 臂的 0 值有一部分可能是被 kind 预算闸遮蔽而非真的不挤压（但 §4 的 `budget_blocks` 满容占比独立支持「换了一道闸」的读法）。
